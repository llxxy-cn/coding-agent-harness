**Date:** 2026-08-09

**Baseline:** `main` @ `5f8d60bbae0280af47e19167074d5d414a6bc70a`
**Status:** Design only — no implementation code

## 1. Overview

A fixed, offline, deterministic demo Web UI for the Coding Agent Harness. It exposes three fixed scenarios through server-rendered pages, using the existing HarnessCore and ApplicationService without duplication. The Web UI is a v0.2.0 bonus feature, not a submission blocker.

### Confirmed Design Decisions

1. Fixed, offline, deterministic demo Web UI — no arbitrary repos, prompts, API keys, or real Provider.
2. Server-rendered pages; no reimplementation of HarnessCore.
3. Synchronous POST: `POST /scenarios/{scenario_id}/runs`
4. No background tasks, queues, polling, WebSocket, or SSE.
5. Global concurrency 1; non-blocking acquire failure returns sanitized 503 busy.
6. Single pytest max 20 seconds; entire request max 60 seconds.
7. Frontend shows static loading only and disables resubmission; security does not depend on frontend.
8. Requests validated before any resource creation: fixed ScenarioId, CSRF, Origin, Host, Content-Type, CSRF-only body.
9. CSRF uses double-submit nonce: hidden form field + `__Host-cah_csrf` Cookie (Secure, HttpOnly, SameSite=Strict, Path=/, no Domain, constant-time comparison).
10. Cleanup failure overrides success: no execution trace returned, fixed sanitized 500 `cleanup_failed`.
11. Trace incomplete → fail-closed; browser receives no partial results or raw exceptions.
12. Human Review Pause scenario uses real `RequestHumanAction`: `TaskStatus.PAUSED_FOR_HUMAN`, tool/patch/test calls all 0, no repo modification, no approval consumed, no `ApprovalBinding`, no approve/reject/resume HTTP endpoint.
13. Single process, single worker.
14. No user login, upload, free-text tasks, real Agent run, keyring, or Git remote operations.

### 2.3 Worker Launch

Explicit subprocess worker entry point. Not fork, not multiprocessing.

**Command:**
```
<trusted_python> -I -m coding_agent_harness.web.worker --config <request_root>/worker-config.json --result <request_root>/worker-result.json
```

**Fixed parameters:**
- `shell=False`
- `-I` flag: isolated mode, no `PYTHONPATH`/`PYTHONHOME` inheritance, no user site-packages
- Arguments: exactly `--config <path>` and `--result <path>`, no other arguments
- `cwd`: app-created fixed safe empty directory (`<request_root>/cwd/`), not shared system temp root
- Environment: fixed minimal allowlist (`PATH`, `SYSTEMROOT`, `WINDIR`, `TEMP`, `TMP`, `TMPDIR`, `LANG`, `LC_ALL`, `PATHEXT`); values frozen at app startup
- stdout/stderr: bounded capture, discarded or sanitized internal diagnostics; not in HTTP, IPC trace, or normal logs

**Process creation flags:**
- Windows: `CREATE_SUSPENDED | CREATE_NEW_PROCESS_GROUP`
- POSIX: `start_new_session=True`

### 2.4 Cross-Platform Process Tree Termination

**Windows (preferred — Job Object with no escape race):**
1. Create Job Object with `JOB_OBJECT_LIMIT_KILL_ON_JOB_CLOSE`
2. Create worker process with `CREATE_SUSPENDED | CREATE_NEW_PROCESS_GROUP`
3. `AssignProcessToJobObject` — assign worker to Job
4. `ResumeThread` — start worker
5. If any step fails (after process creation): terminate suspended process, close all handles, fail-closed
6. On timeout: close/terminate entire Job (all descendants killed)
7. `process.wait()` confirms root exit
8. Query Job active process count — only 0 means termination confirmed
9. Close Job handle (always, regardless of outcome)

**Windows fallback (taskkill):** Only leads to `termination_unconfirmed`. Initial public mode must NOT degrade to taskkill best-effort and still claim termination confirmed.

**POSIX:**
1. `start_new_session=True` creates new session/process group
2. On timeout: `os.killpg(pgid, signal.SIGKILL)` — kills entire group
3. `process.wait(timeout=5)` confirms root exit
4. Check group existence (`killpg(pgid, 0)` raises `ProcessLookupError` if gone)
5. Group no longer exists = termination confirmed

**Normal exit also checks descendants:** Even when worker exits normally, descendant processes (e.g., pytest) may still be alive. `confirm_termination` checks descendants in both timeout and normal exit cases. If descendants alive: terminate entire Job/group, re-confirm.

**Worker normal exit with descendants alive = lifecycle violation:** Returns 500 `worker_lifecycle_invalid`, no trace. Not 200 or 504.

### 2.5 request_root Lifecycle

**Structure:**
```
<request_root>/                   <- parent creates and owns
  worker-config.json              <- parent writes, worker reads
  worker-result.json              <- worker writes, parent reads
  data/                           <- data_root for runtime (SQLite, artifacts)
  repository/                     <- copied repository template
  cwd/                            <- worker's fixed safe empty working directory
```

**Creation:** Parent creates after acquiring global lock. Creates all subdirectories. Writes `worker-config.json`.

**Cleanup:** Parent cleans up entire `request_root` after termination confirmed. Cleanup failure -> 500 `cleanup_failed`.

**Isolation (termination unconfirmed):** Does not clean up potentially occupied directory. Isolates `request_root`, logs random event ID (no paths), returns 500 `termination_unconfirmed`. Subsequent controlled recovery is not part of current HTTP request, not via browser.

### 2.6 HTTPS / Reverse Proxy Trust Boundary

**Two legitimate startup modes:**

**Mode A — Reverse proxy mode:**
- App binds loopback (`127.0.0.1`/`::1`) or private interface (`10.x`/`172.16-31.x`/`192.168.x`)
- Trusted proxy handles HTTPS termination
- Proxy must preserve original Host header
- App does not trust `Forwarded`/`X-Forwarded-Host`/`X-Forwarded-Proto`/`X-Forwarded-For`
- No uvicorn `ProxyHeaders` middleware
- CLI: `coding-agent-harness web --origin https://demo.example.com --bind 127.0.0.1:8000`

**Mode B — Direct TLS mode:**
- App directly public binds (`0.0.0.0` or non-loopback/private)
- CLI must explicitly provide `--tls-cert <path>` and `--tls-key <path>`
- No TLS config -> reject startup
- CLI: `coding-agent-harness web --origin https://demo.example.com --bind 0.0.0.0:8443 --tls-cert cert.pem --tls-key key.pem`

`--origin` alone does not create HTTPS. It declares canonical origin for security validation.

**Local testing:** FastAPI `TestClient` with `base_url="https://testserver"`. Injects fixed HTTPS base URL. Never disables `Secure` or allows `http://` origin.

### 2.7 canonical_origin and Host Authority Validation

**`canonical_origin` startup validation:**
- scheme must be `https`, reject `http://`
- must have hostname
- reject userinfo, path (except `/`), query, fragment
- hostname lowercase
- port normalization: 443 omitted, non-default port retained

**Host header validation:**
- Parse Host header as authority (hostname + optional port)
- hostname lowercase, port normalized (443 omitted)
- Exact match against canonical authority from `canonical_origin`
- Mismatch -> 403

### 2.8 CSRF Request Body Contract

POST form must contain CSRF hidden field, so body is not physically empty. Correct contract:

- `Content-Type`: fixed `application/x-www-form-urlencoded` (parse media type, charset acceptable)
- Body size <= fixed limit (e.g., 4 KiB), checked before parsing
- Parsed body: exactly one `csrf_token` field; duplicate `csrf_token` rejected; no business fields or extra fields
- `scenario_id` from path must match `ScenarioRegistry` fixed allowlist
- Any extra field -> 400 reject (before any resource creation)

**CSRF double-submit nonce:**
- `GET /`: server generates nonce with `secrets.token_urlsafe(32)`
- Same nonce set in hidden form field and `__Host-cah_csrf` Cookie (`Secure`, `HttpOnly`, `SameSite=Strict`, `Path=/`, no `Domain`)
- `POST`: compare hidden field value with Cookie value using `secrets.compare_digest`
- Mismatch -> 403

### 2.9 DemoTraceEvent Discriminated Union

All fields are enum, bounded int, or bool. No free text.

```python
class DemoEventType(str, Enum):
    ACTION_SELECTED = "action_selected"
    POLICY_DECISION = "policy_decision"
    TEST_COMPLETED = "test_completed"
    FEEDBACK_PRODUCED = "feedback_produced"
    TERMINAL_STATUS = "terminal_status"

class ActionSelectedEvent(_FrozenModel):
    event_type: Literal[DemoEventType.ACTION_SELECTED] = DemoEventType.ACTION_SELECTED
    action_kind: DemoActionKind  # enum: read_file, search_code, apply_patch, request_human, ...
    sequence: StrictInt  # Field(ge=0)

class PolicyDecisionEvent(_FrozenModel):
    event_type: Literal[DemoEventType.POLICY_DECISION] = DemoEventType.POLICY_DECISION
    decision: PolicyOutcome  # enum: DENY, ALLOW, REQUIRE_APPROVAL
    reason_code: PolicyReasonCode  # enum: TEST_ASSET_PROTECTION, ...
    sequence: StrictInt

class TestCompletedEvent(_FrozenModel):
    event_type: Literal[DemoEventType.TEST_COMPLETED] = DemoEventType.TEST_COMPLETED
    outcome: TestRunOutcome  # enum: passed, failed, timed_out, ...
    sequence: StrictInt

class DemoFeedbackCode(str, Enum):

    # The domain FeedbackKind has no value for this case.
    INITIAL_FAILURE = "initial_failure"  # harness kind=None, first test failed, no previous result

    CHANGED = "changed"        # harness FeedbackKind.CHANGED (requires previous != None)
    PROGRESS = "progress"      # harness FeedbackKind.PROGRESS
    NO_PROGRESS = "no_progress"  # harness FeedbackKind.NO_PROGRESS
    REGRESSION = "regression"  # harness FeedbackKind.REGRESSION
    LOOP = "loop"              # harness FeedbackKind.LOOP
    ENVIRONMENT_ERROR = "environment_error"  # harness FeedbackKind.ENVIRONMENT_ERROR
    UNPARSEABLE = "unparseable"  # harness FeedbackKind.UNPARSEABLE

class FeedbackProducedEvent(_FrozenModel):
    event_type: Literal[DemoEventType.FEEDBACK_PRODUCED] = DemoEventType.FEEDBACK_PRODUCED
    feedback_code: DemoFeedbackCode  # web-demo enum, not domain FeedbackKind
    sequence: StrictInt

class TerminalStatusEvent(_FrozenModel):
    event_type: Literal[DemoEventType.TERMINAL_STATUS] = DemoEventType.TERMINAL_STATUS
    task_status: TaskStatus  # enum: succeeded, stopped, paused_for_human, ...
    sequence: StrictInt

DemoTraceEvent = Annotated[
    ActionSelectedEvent | PolicyDecisionEvent | TestCompletedEvent | FeedbackProducedEvent | TerminalStatusEvent,
    Field(discriminator="event_type")
]
```

### 2.10 DemoWorkerResult (IPC JSON Top-Level Model)

```python
class DemoWorkerResult(_FrozenModel):  # frozen=True, extra="forbid"
    schema_version: Literal[1]  # fixed
    scenario_id: StrictStr  # parent matches against selected ScenarioConfig
    events: tuple[DemoTraceEvent, ...]  # discriminated union
    terminal_code: TaskStatus  # enum, not StrictStr
```

**Validation:**
- `extra="forbid"` — reject unknown fields
- `schema_version` must be `1`
- `scenario_id` must equal parent's started scenario
- `events` count <= upper limit (e.g., 64)
- `worker-result.json` file bytes <= upper limit (64 KiB)
- Reject trailing data
- `terminal_code` must equal `TerminalStatusEvent.task_status` and `ScenarioConfig.expected_terminal_status`

### 2.11 ScenarioTraceContract

```python
class EventCountRule(_FrozenModel):  # frozen=True, extra="forbid"
    event_type: DemoEventType  # enum
    min_count: StrictInt  # Field(ge=0)
    max_count: StrictInt  # Field(ge=min_count)

class ScenarioTraceContract(_FrozenModel):  # frozen=True, extra="forbid"
    count_rules: tuple[EventCountRule, ...]
    allowed_transitions: tuple[tuple[DemoEventType, DemoEventType], ...]
    required_terminal_status: TaskStatus  # enum
    max_events: StrictInt
```

**Parent validation:**
1. Each event type count within `[min_count, max_count]`
2. Each consecutive event pair in `allowed_transitions`
3. Exactly one `TERMINAL_STATUS` event, at the end
4. `sequence` from 0 continuous
5. `TerminalStatusEvent.task_status` == `DemoWorkerResult.terminal_code` == `ScenarioConfig.expected_terminal_status` == `ScenarioTraceContract.required_terminal_status`
6. Event count <= `max_events`
7. Failure -> 500 fail-closed

### 2.13 State Machine and Finally Order

Explicit state machine — no return in Python `finally`.

**State variables:** `lock_acquired`, `request_root_created`, `worker_handle.process_created`, `termination_confirmed`, `cleanup_succeeded`

**Finally order:**
1. Close result/config file handles
2. Confirm or terminate process boundary (per `WorkerHandle`)
3. Close thread/process/Job handles
4. Compute `safe_to_cleanup = request_root_created and (not process_created or termination_confirmed)`
5. Clean up or isolate `request_root`
6. Release global lock (always, last)
7. Generate response once at function end

**Error priority:** `termination_unconfirmed > cleanup_failed > timeout/trace/internal > success`

### 2.14 Status Code Table

| Scenario | Status Code | Response Body |
|----------|-------------|---------------|
| Global lock acquire failed | 503 | sanitized `busy` |
| 60s total timeout | 504 | sanitized `timeout` |
| Process tree termination unconfirmed | 500 | sanitized `termination_unconfirmed`; request_root isolated |
| Cleanup failed | 500 | sanitized `cleanup_failed` |
| Trace incomplete/invalid | 500 | sanitized `trace_incomplete` |
| Worker lifecycle invalid (normal exit, descendants alive) | 500 | sanitized `worker_lifecycle_invalid` |
| scenario_id not in allowlist | 404 | sanitized `not_found` |
| CSRF/Origin/Host mismatch | 403 | sanitized `forbidden` |
| Content-Type mismatch | 415 | sanitized `unsupported_media_type` |
| Body too large | 413 | sanitized `request_too_large` |
| Body fields invalid | 400 | sanitized `bad_request` |
| Success | 200 | server-rendered result page |

All error responses log only random event ID server-side, no sensitive paths or raw exceptions.
